## Usage

Import the components:

```tsx
import { RadioGroup, RadioGroupItem } from "~/components/radio-group";
```

Basic usage:

```tsx
<RadioGroup defaultValue="1" orientation="horizontal">
  <RadioGroupItem value="1">Credit Card</RadioGroupItem>
  <RadioGroupItem value="2">Paypal</RadioGroupItem>
  <RadioGroupItem value="3">Debit</RadioGroupItem>
</RadioGroup>
```

## With Label

Add a label to describe the radio group.

```tsx
<RadioGroup defaultValue="1" orientation="horizontal">
  <RadioGroupItem value="1">Credit Card</RadioGroupItem>
  <RadioGroupItem value="2">Paypal</RadioGroupItem>
</RadioGroup>
```

## Advanced Usage

When the composite <InlineCode>RadioGroup</InlineCode> doesn't provide enough control, import the raw primitive parts from the base file directly:

```tsx
import { RadioGroup } from "~/components/radio-group/radio-group.base";
```

Or import <InlineCode>RadioGroupBase</InlineCode> (the raw parts namespace) from the composite entry point:

```tsx
import { RadioGroupBase } from "~/components/radio-group";
```

### Root Provider

Use <InlineCode>RadioGroupBase.RootProvider</InlineCode> when you need to access the radio group state outside of the component tree. This pattern uses the <InlineCode>useRadioGroup</InlineCode> hook from Ark UI to create a shared context that both the radio group and external elements can reference.

<ComponentPreview code={RadioGroupRootProviderDemoCode}>
  <RadioGroupRootProviderDemo />
</ComponentPreview>

The key difference:

- **<InlineCode>RadioGroup</InlineCode> (Root)** — manages its own state internally. Use for simple, self-contained radio groups.
- **<InlineCode>RadioGroupBase.RootProvider</InlineCode>** — accepts a pre-created radio group context via <InlineCode>useRadioGroup</InlineCode>. Use when you need to read or control the radio group state from outside the component tree.
